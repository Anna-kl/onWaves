# Запрос к backend — поля `GET /v1/api/Profiles/sitemap`

**Дата:** 13.10.2026. Файл задачи 9 ТЗ от 19.09.2026 не был заведён, поэтому
контракт собран здесь. Дополнение к уже работающему
`BACKEND-REQUEST-2026-07-29-sitemap-profiles.md`: эндпоинт есть, не хватает полей.

## Зачем

Карта сайта и `/catalog` строятся из этого ответа. Сейчас в элементе есть
`link` и `lastModified`. Фронт уже читает `name`, `city` и `mainCategory`,
если они появятся, и без новой выкладки соберёт анкор
`{имя} — {рубрика}, {город}`.

Плоский список slug не даёт ни человеку, ни роботу понять, кто это и какая
услуга. Сегментация каталога по городу и рубрике тоже ждёт эти поля.
Промо-страницы и демо-аккаунты в карту попадать не должны: сейчас три
тестовых slug выкидываются константой на фронте, и её надо удалить, как только
бэк сам перестанет их отдавать.

Персональные данные не просим.

## Что добавить в элемент `items`

| Поле | Тип | Зачем |
| --- | --- | --- |
| `name` | string | Анкор каталога. Фронт поле уже ждёт, в текущем ответе его нет. |
| `city` | string | Город основного места работы. Анкор и будущая разбивка каталога. |
| `mainCategory` | string | Первая рубрика, человекочитаемая, не id и не GUID. |
| `isPromo` | boolean | Промо-страница («не в каталоге, только прямая ссылка») в карту не входит. |
| `isPublic` | boolean | Профиль открыт анониму. Непубличные в ответ не класть. |
| `isTest` | boolean | Демо-аккаунт. Такие профили в ответ не класть. |

`isPublic` и `isTest` — новые относительно запроса 19.09. Пока их нет, фронт
держит список `NOINDEX_PROFILE_SLUGS` (`developer`, `user-example`,
`bussiness`). Когда демо перестанут приходить в sitemap, список удаляется.
Страница демо при этом остаётся открытой по прямой ссылке: это показ мастерам,
а не 404. В индекс её не кладём отдельно, мета-тегом.

Пустые `name`, `city`, `mainCategory` допустимы: фронт пропускает пустую часть
анкора и падает обратно на slug. Не выдумывать рубрику и город, если их нет
у профиля.
