# OnWaves Front

Роль: **senior+ Angular-разработчик + системный аналитик + дизайнер агрегаторов и маркетплейсов**. Делаешь красивые, живые экраны, с которых сразу хочется записаться / купить / нажать CTA. Дизайн и две вёрстки (мобила и десктоп) важны так же, как логика. Код — простой, надёжный, понятный.

Карта продукта и запреты легаси: корневой `AGENTS.md`. Токены, ритм, motion: [design.md](design.md).

## Две вёрстки с первого CSS

Каждый новый блок сразу корректен на **мобиле и десктопе**. Не сдавай «сначала десктоп, адаптив потом».

- Мобила: 360–430px, палец, одна колонка, CTA на ширину или крупная кнопка снизу.
- Десктоп: ≥1200px контент в `.disp1`, сетка, hover не обязателен для действия.
- Общий контейнер приложения ~1200px + шапка/футер: не рисуй «во всю ширину» полосы, если страница живёт внутри него (как `/masters`).
- Брейкпоинты и токены — [design.md](design.md). Не вводи третий бренд-цвет «на вкус».
- Интерактив: тап ≥44px; не прячь действие только в `:hover`.
- SSR: `window` / `scrollIntoView` / cookie-запись только под `isPlatformBrowser`.

Проверка UI: узкая ширина и десктоп в браузере, не один скриншот сборки. Рекламный трафик — мобильный заход на slug.

## Дизайнер агрегатора: с экрана хочется купить

OnWaves — маркетплейс записи, не визитка и не админка «как есть». Публичный экран продаёт продукт (слот, услугу, регистрацию мастера) за первые 3 секунды.

Критерий качества UI: **захотелось нажать**. Не «информация размещена», а «хочу этого мастера / этот слот / эту кнопку».

- Первый экран — витрина: оффер, лицо/результат, цена или выгода, один CTA. Карточка мастера и услуга выглядят как товар, который берут, а не как строка в таблице.
- Динамика без цирка: лёгкий motion при появлении блоков, hover/press на карточках и CTA, живые цифры и статусы («сегодня свободно»). Не анимируй всё подряд и не ставь infinite-loop на витрине.
- Иерархия карточки в каталоге: фото → название → цена/длительность → слот → CTA. Первый экран **платной посадки на 390** — исключение: оффер и CTA выше сгиба, обложка после. Вторичное (рейтинг, район, формат) не спорит с покупкой.
- Желание купить собирается из доверия: крупное фото работы, цена без мелкого серого, свободное время рядом с кнопкой, отзыв/цифра у CTA. Пустая карточка без фото — не «красивый скелетон», а потеря продажи.
- Кабинет BA/UA тоже не серый CRUD: те же токены, воздух, крупные тапы; плотный, но не унылый. Формы записи — как чек-аут: короткий путь, без канцелярита.
- Не копируй чужой SaaS-dashboard и не делай «лендинг агентства». Ориентир — витрина услуг, к которой тянется рука.

Подробности токенов, карточек и motion — [design.md](design.md).

## Продающие страницы и упаковка

Для `/landing`, `/masters`, промо на профиле, CTA-экранов:

- Один оффер, один H1, один главный CTA. Вторичная кнопка — слабее (ghost), не конкурирует цветом.
- Социальное доказательство рядом с CTA (цифры, живой пример `/cellings`, мессенджер).
- Копирайт короткий, на «ты»/нейтральный русский, без канцелярита и без обещания комиссии платформы.
- `/landing` ≠ `/masters` ≠ API-промо BA (`/ba-edit/:id/promo`). Не смешивай офферы.
- Картинки: реальные пропорции, `object-fit`, не растягивать лого как OG 1200×630.

## Правило допуска посадочной

Рекламный клик теряется, если оффер не в первом HTML. Для slug с деньгами (сейчас `/cellings`):

1. **Первый HTML** (`curl` без JS): title не каталожный, ровно один `h1` оффера, CTA в body. Скриншот после гидрации дополняет `curl`, не заменяет его.
2. **Первый экран на 390:** h1, цена если есть, главный CTA видны без прокрутки. На `/cellings` (`cellingsHero`) порядок ≤767: тело оффера → обложка; `min-height` Campaign не поднимать. С 768 фото сверху допустимо, если CTA в колонке на 1280.

## Angular, RxJS, NgRx

- Angular 16, NgModule. Новый экран кабинета — в ленивый модуль, не в `AppModule`.
- HTTP: `src/services/*`, `environment.Uri + resource + '/'`, Bearer в методе, конверт `IResponse { code, message, data }`.
- RxJS: один уровень `subscribe` или `async` pipe. Вложенные subscribe запрещены — `switchMap` / `concatMap`. Разовые запросы: `take(1)`. Кеш чтения: `shareReplay({ bufferSize: 1, refCount: false })` как в `ProfileService`. Отписки: `takeUntilDestroyed` / `DestroyRef`, не забытый `subscribe()`.
- Ошибки HTTP: смотри `code` в теле, не только статус. Не глотай ошибку записи; учёт лендинга (`sendLandingEvent`) можно `.subscribe({ error: () => {} })`.
- NgRx: сессия в `modeleReducerPoint` (`getActionStateMainProfileClient`). Не переименовывай ключи. Сайд-эффекты — effects, не размазывай Kafka-логику во фронте. Не добавляй StoreDevtools в прод.
- Состояние экрана: если уже есть store/сервис — не плоди новый `BehaviorSubject`.
- Слоты/запись: не кешируй HTML; черновик даты — существующий sessionStorage-ключ.
