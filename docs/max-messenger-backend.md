# Поле `max` (мессенджер MAX) — что нужно от бэкенда

Фронт уже реализован. Чтобы кнопка «Написать в MAX» на публичной странице бизнеса
заработала «вживую», бэкенду нужно **хранить, принимать и отдавать** новое поле профиля
бизнеса — `max`. Ниже — полный контракт.

## 1. Контекст: почему нельзя как у WhatsApp

Кнопка WhatsApp строит ссылку из телефона: `https://wa.me/{phone}`. У **MAX так нельзя** —
у мессенджера нет ссылки по номеру (приватность). Ссылка ведёт только на профиль:

- `https://max.ru/u/<длинный-хеш>` — ссылка из приложения (аватар → QR → «Поделиться»);
- `https://max.ru/<username>` — если у пользователя задан username;
- `@username` — короткая форма.

Поэтому MAX-контакт **нельзя вычислить из телефона** — его нужно хранить отдельно,
ровно как `telegram`. Бизнес вводит его сам в редакторе контактов.

## 2. Поле

| Свойство | Значение |
|---|---|
| Имя | `max` |
| Тип | `string`, **nullable / необязательное** |
| Назначение | контакт бизнеса в мессенджере MAX (username или ссылка) |
| Пример значений | `https://max.ru/u/AbC123...`, `max.ru/company`, `@company`, `company` |
| Аналог в модели | точно как существующее поле `telegram` |

Фронт **не навязывает** формат ввода: сохраняет то, что ввёл бизнес, а при клике сам
нормализует в URL (`@user` / `max.ru/…` / голый username → `https://max.ru/…`; полный
`http(s)://` — как есть). Бэку достаточно хранить строку как есть.

Рекомендации по хранению:
- колонка в таблице профиля бизнеса, `VARCHAR(255) NULL` (миграция — добавить nullable-столбец);
- тримить пробелы; пустую строку сохранять как `NULL`;
- жёсткую валидацию формата делать **не обязательно** (фронт нормализует). Если хочется —
  допустимы: строка, начинающаяся с `http(s)://max.ru/`, `max.ru/`, `@` или `[A-Za-z0-9_.-]+`.

## 3. Эндпоинты, которые надо обновить

Модель профиля бизнеса на фронте — `IViewBusinessProfile`. Поле `max` нужно добавить в
DTO/сущность на бэке и провести через те же ручки, где уже ходят `telegram` / `whatsApp`:

### 3.1. Чтение профиля (обязательно)
```
GET  profiles/get-full-baprofile/{id}
```
Используется и публичной страницей бизнеса, и редактором. **Ответ должен содержать поле
`max`** в объекте профиля. Без этого кнопка не покажется (фронт скрывает её при пустом `max`).

### 3.2. Обновление профиля (обязательно)
```
PUT  profiles/update-baprofile/{id}
Authorization: Bearer <token>
Body: IViewBusinessProfile   // включает max
```
Принять и **сохранить** `max` из тела запроса.

### 3.3. Создание профиля (желательно)
```
POST profiles/business
Body: IViewBusinessProfile   // включает max
```
Если MAX можно указать уже при регистрации — принять и сохранить `max` здесь тоже.

## 4. Примеры

Фрагмент профиля в ответе `GET get-full-baprofile/{id}` и в теле `PUT update-baprofile/{id}`:
```json
{
  "id": "2b48605e-cbf2-4505-bbed-4bea2bbf5d0a",
  "name": "Натяжные потолки",
  "phone": "79001234567",
  "whatsApp": "79001234567",
  "telegram": "@company",
  "max": "https://max.ru/u/AbC123xyz",
  "webSite": "https://example.ru"
}
```

- Поле опциональное: если бизнес не заполнил MAX — вернуть `"max": null` или не присылать ключ
  (фронт трактует оба варианта как «не задано» и кнопку не показывает).

## 5. Опционально: трекинг клика по MAX

Клики по контактам логируются вашей ручкой посещений:
```
GET  profiles/get-reference/{id}?option=<action>[&whoIs=<userId>]
```
Сейчас используются `option`: `click_call`, `click_message`, `click_record`.
Кнопка Telegram и (пока) кнопка MAX **клик не трекают**. Если нужен отдельный подсчёт
переходов в MAX — заведите на бэке новый допустимый `option` (например `click_max`),
и фронт повесит на кнопку вызов `clickContact('click_max')`. Скажите — добавлю на фронте.
