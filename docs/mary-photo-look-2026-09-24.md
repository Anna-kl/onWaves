# Mary: подбор услуги по фото

**Дата:** 24.09.2026. **Статус:** черновик ТЗ, код не начат.
**Профиль:** публичный slug `mary`. Механизм читает прайс профиля из базы, имя Mary в промпт не зашито.

Это не граф калькулятора (`calculators/quotes`, плеер, смета потолков) и не легаси `cellings-offer`. Клиент не считает цену. Модель выбирает id услуг, цену и длительность подставляет сервер из `Services`.

Мессенджер MAX здесь не подключаем. «Max» в этом ТЗ — модель `GigaChat-2-Max`.

---

## 1. Как включить GigaChat 2 Max

Ключ и scope уже в `Flask Api/promt.py`: `GIGACHAT_API_PERS`. Голосовой клиент остаётся на `model="GigaChat"` (Lite, без зрения). Для фото — **второй** клиент, тот же ключ, другая модель. Пакет в проекте: `langchain-gigachat==0.3.12`. Его не поднимаем ради `content_blocks` из 0.5: в 0.3.12 фото уже уходит через `upload_file` и `attachments`.

```python
vision = GigaChat(
    credentials=key,
    scope="GIGACHAT_API_PERS",
    model="GigaChat-2-Max",
    temperature=0.2,
    max_tokens=800,
    timeout=60,
    verify_ssl_certs=False,  # как у голоса, пока ключ живёт в promt.py
)

uploaded = vision.upload_file(("look.jpg", jpeg_bytes))
message = HumanMessage(
    content=[
        {"type": "text", "text": user_text},
        {"type": "image_url", "image_url": {"giga_id": uploaded.id_}},
    ]
)
reply = vision.invoke([system, message])
vision.delete_file(uploaded.id_)
```

Почему так, а не смена глобального `model` в `promt.py`:

- Lite не анализирует изображения. Id `GigaChat` / `GigaChat-2` списывает бесплатные токены Lite и фото не видит.
- `GigaChat-2-Max` и алиас `GigaChat-Max` списывают пакет Max (freemium физлица: 25 млн токенов на 12 месяцев, дальше 650 ₽ / 1 млн).
- В одном сообщении — одно изображение. Два-три кадра — два-три `HumanMessage` в одном `invoke`, у каждого свой `giga_id`. Потолок API: 10 изображений на запрос, 15 МБ на файл.
- Форматы хранилища: jpeg, png, tiff, bmp. HEIC и webp до модели не доходят.
- Файл после ответа удаляем. Идентификатор файла наружу не отдаём.
- `verify_ssl_certs=False` в новый модуль не копируем отдельной «улучшенной» копией ключа. Клиент создаётся рядом с голосовым и берёт тот же ключ. Вынос ключа в env — отдельная задача, в этот заход не входит.

Один процесс Flask и freemium Max: генерация в **один поток**. Второй гость не стартует второй вызов. Пока идёт запрос, эндпоинт отвечает «уже разбираем другое фото, подождите» и не ставит тихую очередь.

Повторные ходы фото не шлют. В сессии остаётся короткое `visual` из первого ответа (что модель увидела). Иначе каждый вопрос заново тарифицирует до 1792 токенов на снимок.

Оценка сессии: первый ход с 1–3 фото и прайсом около 4–8 тыс. токенов, два уточнения текстом ещё 2–4 тыс. Ориентир **4–8 ₽** на Max, если снимки не пересылать. На 25 млн бесплатных токенов — порядка 3 тыс. таких сессий.

## 2. Кто и зачем

Гость на `https://onwaves.online/mary` (телефон 360–430 и десктоп). Хочет понять, какая услуга из прайса Mary ему подходит, по фото рук, волос, бровей или ресниц, и записаться. Мастер прайс не размечает заново и анкету в кабинете не собирает.

Первый экран профиля не меняется: один `h1` — имя, title и каноникал как сейчас. Кнопка подбора появляется в колонке услуг после загрузки профиля, это не оффер первого HTML и не slug Директа.

Купон `welcome-pilot-2026-09` не трогаем. Подбор по фото скидку не обещает и не рисует.

## 3. Сценарий

1. В колонке услуг кнопка «Подсказать по фото».
2. Гость добавляет 1–3 снимка и по желанию одну строку комментария («хочу как на фото, свои ногти»).
3. Сервер смотрит снимки и прайс. Ответ один из двух:
   - **уточнение** — до трёх коротких вопросов с вариантами-кнопками, не свободное сочинение;
   - **подбор** — 1–3 услуги карточками: название, цена и длительность из базы, одна фраза «почему».
4. Уточнений не больше двух кругов. На третьем ход модель обязана вернуть подбор или честный отказ.
5. Отказ («по фото не разобрать») — текст и кнопка в обычный прайс `/mary/choose-service`. Выдуманной услуги нет.
6. На карточке главная кнопка «Записаться». Ведёт в уже существующий `goBooking(serviceId)`: слот или сразу подтверждение, как у услуги в акции. Вторая кнопка — «Другая услуга», в `/mary/choose-service`.
7. Поле ввода на экране подбора скрыто. Вопросов «а можно ещё дешевле» в этом контуре нет.

Запись, слоты и гостевой `quick-register` не меняются. Ответ модели в комментарий записи не пишем: это не смета потолков и не `ow-calc-handoff`.

## 4. Контракт Flask

Новый модуль рядом с голосом, не ветка внутри `get_annotation`. Голос и `POST /api/upload/mpeg` не меняются. `POST /api/upload/photo` (файл на диск) не используем.

База: `Services` по `ProfileUserId`, как в `upload_mpeg`. В промпт уходит ужатый каталог: `id`, имя, группа, длительность в минутах, цена строкой из JSONB `Price` (`Price` / «от StartRange» / диапазон). `About` обрезается до 120 символов. Пустой прайс — сразу отказ без вызова модели.

### 4.1 Старт

`POST {UriAI}look/start`  
`multipart`: `profileId` (GUID мастера), `comment` (до 200 символов), `file` 1–3 штуки, `requestId`.

Клиент перед отправкой: длинная сторона ≤ 1280 px, jpeg quality около 0.8, HEIC → jpeg. Сервер всё равно проверяет: jpeg/png, каждый файл ≤ 4 МБ, суммарно ≤ 8 МБ. Иное — 400 с человеческим текстом, модель не вызывается.

Ответ:

```json
{
  "sessionId": "uuid",
  "status": "ask",
  "visual": "короткие ногти, светлый гель, скол на большом",
  "questions": [
    { "id": "q1", "text": "Наращивать или своё покрытие?", "options": ["Свои ногти", "Наращивание", "Не знаю"] }
  ],
  "services": []
}
```

`status: "recommend"` — `questions` пустой, `services` 1–3:

```json
{
  "id": "guid-из-Services",
  "name": "Маникюр с покрытием",
  "priceText": "1 800 ₽",
  "durationMin": 90,
  "why": "По фото покрытие своё, без наращивания"
}
```

`status: "unknown"` — оба списка пустые, `message` для гостя.

Цены и имена в `services` сервер берёт из строки `Services` по id. Текст модели в эти поля не попадает. Id вне каталога отбрасывается. Если после фильтра не осталось id, а модель просила `recommend`, ответ становится `unknown`.

### 4.2 Уточнение

`POST {UriAI}look/answer`  
JSON: `sessionId`, `requestId`, `answers: [{ "id", "option" }]`. Файлов нет.

Сессия живёт в памяти процесса 30 минут: `visual`, каталог id, число кругов, последний ответ. Фото в сессии нет. Повтор того же `requestId` возвращает сохранённый ответ и модель не зовёт. Чужой или протухший `sessionId` — 404.

### 4.3 Что обязана вернуть модель

Один JSON, без текста вокруг. Поля: `status` (`ask` | `recommend` | `unknown`), `visual` (до 300 символов, только то, что видно), `questions` (0–3, у каждого 2–4 `options`), `serviceIds` (только из переданного каталога), `why` (одна фраза на каждый id).

Промпт запрещает новую услугу, скидку, «примерно N рублей» и медицинские советы. Если кадра не хватает — `ask`, не угадывание. После двух кругов вопросов в промпт дописывается: вопросы больше нельзя, только `recommend` или `unknown`.

Температура 0.2. Сломанный JSON — один повтор. Второй сбой — `unknown` и текст «Не получилось разобрать фото, выберите услугу в прайсе».

## 5. Фронт

Кнопка и панель — в публичной колонке профиля (`profile-ba`), только если slug `mary` и прайс не пустой. Кабинет BA и превью `profilebisacc` без этой кнопки.

Панель в потоке страницы, не фиксированный слой. В расчёт `calculator-stage` её не добавляем: шапку и нижнее меню она не перекрывает.

Мобила и десктоп сразу: кнопка на ширину колонки, тап ≥ 44px, карточка услуги — фото гостя миниатюрой, название, цена, «Записаться». Цвета только токены (`$green-dark`, `$green-basic`, `$green-light`). Шрифт Montserrat.

Состояния: загрузка («Смотрю фото…»), вопросы кнопками, подбор, отказ, ошибка сети. Ошибка — «Не вышло отправить фото, попробуйте ещё раз», не код HTTP.

`window` / файл / сессия — только в браузере. В SSR-HTML нет снимка, вопросов и цен подбора. HTML-кеш `server.ts` для `/mary` не начинает хранить персональный проход: панель не сериализуется.

Запись: тот же `goBooking(serviceId)`, что у акции. Новый роут воронки не заводим.

Учёт, когда кнопки реально есть в Метрике и в кабинете VK Ads (имя = action, не gtag):

| action | когда |
|---|---|
| `mary_look_start` | ушёл первый запрос с фото, один раз на сессию |
| `mary_look_recommend` | показан подбор |
| `mary_look_book` | нажали «Записаться» с карточки подбора |

`calculator_start` / `calculator_complete` / `calculator_max` не используем: это цели графа, у `calculator_start` уже id `637119448`.

## 6. Границы

- Модель не создаёт запись и не пишет в `Records`.
- Снимок не кладём в S3 витрины и не показываем мастеру. После ответа файл в хранилище GigaChat удаляется.
- Контакты гостя модели не передаём.
- Одновременно один вызов Max на процесс. Повтор с тем же `requestId` модельный вызов не дублирует.
- На устройство (`uuid-ocpio`, если есть, иначе сессионный ключ) не больше 8 стартов в сутки. Дальше — отказ текстом и ссылка на прайс, без вызова модели.
- Ключ из `promt.py` в логи, в ответ API и в новый файл не копируем.

---

## 7. Приёмка

- Голос `upload/mpeg` отвечает как раньше, модель запроса по-прежнему Lite.
- На `/mary` с телефона: фото → либо вопросы с кнопками, либо 1–3 услуги с ценой из прайса. Цена на карточке совпадает с карточкой услуги в колонке.
- Id, которого нет в прайсе, на экран не попадает.
- Второй круг вопросов уходит без файла; в хранилище GigaChat файл после первого ответа удалён.
- «Записаться» открывает `choose-date` или `confirm-record` этой услуги, слоты те же, что из прайса.
- `/cellings` и плеер калькулятора не меняются. На `/mary` один `h1`, title карточки, купон в первом HTML по-прежнему не виден.
- Два старта подряд: второй, пока первый думает, получает текст подождать, а не второй параллельный вызов.
