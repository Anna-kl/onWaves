# График: перерыв на весь график и закрытые часы на дату

Для агента. Это решение мастера от 20.10.2026. Оно новее `docs/backend/schedule-master-week-2026-10-19.md`.
Где документы спорят — верно это.

Фронт уже рисует экраны в `src/app/baedit/components/grafik-week/`.
Бэк уже содержит таблицу `ScheduleBlocks` и запись перерыва на карточку в `ScheduleWeekStore`.
Миграция на базу сама не накатывается. SQL ниже человек выполняет сам. Процесс API из отладки сам не перезапускать.

## Нельзя

- Не удалять и не пересоздавать `Schedule` и `DaysOfSchedules`. Строки дней не удалять. `Record.DaysOfScheduleId` не перевешивать.
- «Выходной» — `IsDayOff`, строка остаётся.
- Не возвращать 409 «профиль ещё на старом графике». `ScheduleMode` новый экран не прячет. Успешный `GET schedules/week/{id}` показывает новую неделю. Ошибка ручки — старый `GrafikComponent`. Старый экран не удалять.
- Не трогать воронку записи (`choose-service`, `choose-date`, `confirm-record`), `/notes`, промо, купоны, `/cellings`.
- Не переименовывать BA, `grafik`, `IViewSchedule`, ключи стора, папку `enviroments`.
- Слоты считает только сервер. «Сегодня» — `todayDate` с сервера, не часы телефона.
- Не выполнять SQL и не убивать процесс Visual Studio, пока человек сам не попросил.

## Два разных смысла

Не смешивать.

| | Перерыв | Закрытые часы |
| --- | --- | --- |
| Кнопка | «Добавить перерыв» | «Закрыть часы» |
| На кого | На все дни этой карточки графика | Только эта дата |
| Подпись | «Работает на все дни графика» | «Только эта дата. Другие дни этого графика не меняются.» |
| Где лежит | `Schedule.StartOfBreak` / `EndOfBreak` | Таблица `ScheduleBlocks`, ключ `DaysOfScheduleId` |
| Сколько | Один интервал | Сколько угодно |
| Галочки «постоянный / только этот день» | Нет | Нет |

День, у которого перерыв уже свой и он другой, при сохранении общего перерыва не переписывать.

«Убрать» у перерыва снимает перерыв с карточки и с дней, которые его повторяли. Закрытые часы этой даты при этом не трогать.

«Убрать» у закрытых часов снимает только этот интервал этой даты.

## Экран дня

Роут ` /ba-edit/:id/schedule/day/:date `. Назад — на `/ba-edit/:id/schedule`, не на `schedule/day` без даты.

Прошедшая дата (`day.date < week.todayDate`): кнопка «Изменить» на неделе неактивна, сохранить с экрана дня нельзя. Сегодня и будущие дни, включая выходной, можно менять.

Время везде — поля `input type="time"` с подписями **С** и **До**. Кнопок «− / +» для часов нет. Пустые С или До, либо конец не позже начала — сохранение не уходит, мастер видит, что время нужно указать.

Блоки экрана, сверху вниз:

1. Выходной. Переключатель как сейчас.
2. «Клиенты увидят» и полоска дня.
3. Часы дня: С и До. Это начало и конец работы.
4. «Добавить перерыв». После нажатия — панель с подписью «Работает на все дни графика» и обязательными С и До. Кнопка «Убрать».
5. «Закрытые часы». Каждая пара — такая же панель С и До. Кнопка внизу — «Закрыть часы», не «Закрыть окно».
6. «Только этот день» и «На все {день недели}». Закрытые часы на другие дни недели не копируются.

Постоянный график (`schedule/template`) задаёт начало и конец дня теми же полями С и До.

## Сервер

`PUT schedules/day/{profileId}`:

- `break` — интервал или `null`.
- `breakForSchedule: true` — записать этот перерыв на карточку с теми же часами работы и на дни, которые повторяют прежний перерыв карточки. Свой другой перерыв дня не затирать.
- `breakForSchedule: false` и мастер перерыв не трогал — карточку не очищать.
- `blocks` — полный список закрытых часов этой даты. `null` в запросе значит «не трогать». Пустой список снимает все заглушки даты. На другие даты не копировать.
- Прошедшая дата — 400 «Прошедшую дату менять нельзя».
- Конец не позже начала и окно вне рабочего дня — 400.

`GET schedules/week/{profileId}` отдаёт у дня `break`, `breakShared` и `blocks[]`.

Слоты (`get-free-slot*`, `days-in-month` с длительностью, перенос записи) не отдают время перерыва карточки и интервалы `ScheduleBlocks` этой даты. Калькулятор слотов не дублировать: заглушки передаются ему занятыми окнами.

Запись, которая попала в закрытые часы, остаётся. Мастер видит конфликт. Запись сама не отменяется.

## SQL, которое выполняет человек

```sql
CREATE TABLE IF NOT EXISTS public."ScheduleBlocks" (
    "Id" uuid NOT NULL,
    "DaysOfScheduleId" uuid NOT NULL,
    "Start" interval NOT NULL,
    "End" interval NOT NULL,
    CONSTRAINT "PK_ScheduleBlocks" PRIMARY KEY ("Id"),
    CONSTRAINT "FK_ScheduleBlocks_DaysOfSchedules_DaysOfScheduleId"
        FOREIGN KEY ("DaysOfScheduleId") REFERENCES public."DaysOfSchedules" ("Id") ON DELETE CASCADE
);

CREATE INDEX IF NOT EXISTS "IX_ScheduleBlocks_DaysOfScheduleId"
    ON public."ScheduleBlocks" ("DaysOfScheduleId");
```

После SQL — перезапуск API. Пока крутится старый процесс, перерыв на карточку и закрытые часы не сохраняются.

## Готово, когда

- Прошедший день на неделе нельзя открыть кнопкой «Изменить». Сегодня открывается.
- «‹ Неделя» возвращает на неделю, в консоли нет `NG04002` на `schedule/day`.
- «Добавить перерыв» требует С и До и пишет подпись «Работает на все дни графика». Галочек нет.
- Тот же перерыв виден на других днях этой карточки. День со своим другим перерывом не изменился.
- «Закрыть часы» закрывает интервал только на этой дате. Соседний день той же карточки этот интервал не получил.
- Клиентский слот внутрь перерыва и внутрь закрытых часов не попадает.
- Старые карточки графика и записи на них живы.
