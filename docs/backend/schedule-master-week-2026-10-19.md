## Жёсткое правило миграции

Плавный перенос. Таблицы `Schedule` и `DaysOfSchedules` не удалять и не пересоздавать.
Строки дней не удалять и не переподвешивать: записи держатся за `Record.DaysOfScheduleId`.
«Выходной» — это `IsDayOff = true`, строка остаётся.
Схема только добавляет колонки и новые таблицы. Старые карточки остаются контейнерами своих дат.
`ScheduleMode = 0` возвращает старый экран. Старый UI (`GrafikComponent`, `modal-calendar`) в этой задаче не удаляется.

Пока у дня пустые новые поля, эффективные часы равны часам его карточки. Поведение до переноса профиля побитово прежнее.

## Что меняется для мастера

Два уровня:

1. Постоянный график по дням недели. Сам повторяется на 8 недель вперёд, но только после того, как мастер его подтвердил.
2. Исключение на конкретную дату (`Source = Manual`): другие часы, перерыв или выходной. Живёт своими часами, пока мастер не нажмёт «Вернуть».

Правка шаблона не затирает даты `Manual` и возвращает их в `skipped[]`.

Не трогать: воронку записи, `/notes`, промо, купоны, `/cellings`. Имена BA, `grafik`, `IViewSchedule` не переименовывать. Слоты считает сервер.

## Модель

Колонки дня в `DaysOfSchedules`, все необязательные: `StartOfWork`, `EndOfWork`, `StartOfBreak`, `EndOfBreak`, `HasOwnBreak` (default false), `IsDayOff` (default false), `Source` (0 Legacy, 1 Template, 2 Manual), `UpdateDate`.

Эффективные часы = поля дня, если заполнены, иначе поля карточки. Функция `EffectiveSchedule.For(day, schedule)`. `Period` и `GapAfterMinutes` всегда с карточки.

Новая таблица `ScheduleWeekdays`: 7 строк на профиль, уникальный индекс `(ProfileUserId, DayOfWeek)`, Пн = 1 … Вс = 7.

У профиля одна карточка `Schedule.IsTemplate = true` — контейнер новых дат, в ней же шаг сетки и пауза. Старые карточки в новом UI не показываются.

`ProfileUser.ScheduleMode`: 0 старый экран, 1 новый. `ScheduleTemplateConfirmed`: пока false, генератор новые даты не создаёт.

## Перенос одного профиля

`ScheduleMigrator.Migrate(profileId, dryRun)` — одна транзакция. Сверка не сошлась — откат, профиль остаётся на старом экране.

1. Снимок «до» в `ScheduleMigrationLogs`: дни, записи включая отменённые, слоты на 28 дней.
2. Создать контейнер «Постоянный график». `Period` и пауза — как у активной карточки с наибольшим числом будущих дат.
3. В каждую строку дня (активные и неактивные, прошлые и будущие) скопировать часы карточки, `HasOwnBreak = true`, `Source = Legacy`.
4. Неактивные карточки больше не трогать. Дубль даты: строка с живыми записями остаётся рабочей, пустая получает `IsDayOff`, не удаляется. Записи в обеих строках — `NeedsReview`, профиль не переводится.
5. `ScheduleWeekdays` — самое частое сочетание часов за последние 8 недель и все будущие. День недели без дат — выходной. Подтверждение мастера обязательно.
6. `ScheduleMode = 1`. Снимок «после»: те же id дней, те же пары «запись → день», те же слоты.

`Unmigrate` очищает поля только у строк Legacy, чьи часы совпали с карточкой. Строки и записи не трогает.

Генератор создаёт недостающие даты в контейнере на 56 дней и никогда не меняет существующие строки. Ночная задача — только при `ScheduleMode = 1` и подтверждённом шаблоне.

Старые методы записи (`add-schedule`, `update-schedule`, `DELETE schedules/{id}`, `checked-day`) для `ScheduleMode = 1` отвечают 409, чтобы старая вкладка не удалила карточку каскадом.

## Фронт, когда бэк отдаст методы

Роут `/ba-edit/:id/schedule` остаётся. `GrafikComponent` смотрит `scheduleMode`: 0 — старый экран без изменений, 1 — новые компоненты в `BaEditModule`, роуты в `ba-edit.module.ts`.

| Экран | Роут | Компонент |
| --- | --- | --- |
| Неделя | `schedule` | `GrafikWeekComponent` |
| Один день | `schedule/day/:date` | `GrafikDayComponent` |
| Постоянный график | `schedule/template` | `GrafikTemplateComponent` |

Методы в `src/services/schedule.service.ts`: `getWeek`, `saveDay`, `resetDay`, `getTemplate`, `saveTemplate`, `saveWeekday`. Bearer в методе. `IViewSchedule` не менять. Поле `scheduleMode` — в `IViewBussinessProfile` и `copyProfile`. Нет поля — считать 0.

Часы, «сегодня» и ближайший рабочий день приходят с сервера. Конфликты записей показывает `conflicts[]`, записи не отменяются.
