# WorkLocation — геокодирование городов (спецификация для бэкенда)

Контекст: для разъездной работы (`WorkLocationType.Mobile`) в WorkLocation хранится
список городов `cities[]`. Фронт ставит маркер на карте для каждого города.

## Подход: координаты достаются в динамике (без хранения)

Координаты городов **не сохраняются** в БД. Фронт геокодирует каждый город
на лету через существующий endpoint — и в форме адреса, и при показе карточки:

```
GET /v1/api/dictionaries/geo?address={country, region, city}
-> { "lng": 37.61, "lat": 55.75 }
```

Вызывается по одному разу на каждый город. `WorkLocation` остаётся без
координатных полей по городам — только `cities[]`.

## Опционально: батч-геокодинг

Единственная возможная доработка бэка — свести N запросов к одному
(если число городов большое). **Не обязательно.**

| Метод | URL | Auth | Описание |
|-------|-----|------|----------|
| POST | `/v1/api/dictionaries/geo/batch` | Нет | Геокодировать список адресов разом |

**Request:**
```json
{
  "addresses": [
    "Россия, Московская обл, Кашира",
    "Россия, Московская обл, Озёры",
    "Россия, Московская обл, Ступино"
  ]
}
```

**Response 200:**
```json
{
  "code": 200,
  "data": [
    { "address": "Россия, Московская обл, Кашира", "lng": 38.16, "lat": 54.84 },
    { "address": "Россия, Московская обл, Озёры",  "lng": 38.55, "lat": 54.85 },
    { "address": "Россия, Московская обл, Ступино", "lng": 38.08, "lat": 54.89 }
  ]
}
```

Порядок ответа = порядок запроса; для не найденных адресов `lng/lat = null`.

## Что уже сделано на фронте

- Форма адреса (создание и редактирование): для `Mobile` каждый выбранный
  город геокодируется через `GET /geo` в динамике, маркеры выводятся на карте
  (`app-my-ycomponent [geoList]`). Координаты нигде не сохраняются.
- При появлении `POST /geo/batch` — заменить N вызовов `getPoint` на один запрос.
